Chapter 2 · Tokens and cost

Why long AI chats get slow, and the habit that fixes it

I built this website in one long chat with an AI agent. By the evening, even a quick “looks good” took ages. Here’s what was going on, and what I changed because of it.

24 November 2026 · 6 min read

The 30-second version

  • AI tools count text in tokens, chunks of a few letters, and every token the AI reads or writes counts against your plan’s usage limit.
  • Each new message makes the AI re-read the whole chat, so the cost grows with the chat, not with your message.
  • The biggest win is free: one chat per task, with the important bits saved to a file in between.

On 24 November I built most of this website in one Claude Code chat, from morning to evening.

Colours, the home page, research on line spacing, a build log, a pile of new ideas: all in the same conversation. It worked well. By the evening my job was mostly to check the result and confirm it looked good, which is about as easy as work gets. Even those quick confirmations started to take ages.

Nothing was broken. Every reply was dragging my whole day along with it, and every re-read came out of my plan’s usage limit.

What a message actually costs

Token
= a small chunk of text, often part of a wordAI models read and write in tokens, and that is what your usage counts.
Looks␣good␣to␣me.

Roughly how a short phrase gets cut up (␣ marks a space). The exact split depends on the model.

Anthropic puts a Claude token at about 3.5 English characters on earlier models. Claude 4.7 and later cut the same text finer, into about 30% more tokens, so the same chat uses more of your limit on a newer model. Tokens count in both directions, for what the AI reads and for what it writes.

None of this costs me money, because I keep usage credits (once called extra usage, in Settings > Usage) switched off. With them off, work stops when I reach my plan’s usage limit and waits until the limit resets. Every token moves me closer to that ceiling instead of adding to a bill.

Every message carries the whole chat

The model has no memory between messages. So each time I pressed send, Claude Code sent it the entire conversation again: every earlier message, every file it had opened, every result it got back. So even a one-line confirmation carried the whole day with it.

Recent text is cached, so re-reading it is charged at a lower rate than new text. A lower rate still adds up when the pile is a day long.

The chart is an illustration with made-up, equal-sized messages, not my real chat. In it, 48 of the 78 blocks the long chat re-reads belong to tasks that were already finished, and they add nothing to the answer. A fourth task would add 12 more wasted blocks to every message. So the cost of a message depends on the length of the whole chat far more than on your own words.

What I changed

  1. One chat per task. When you switch to something unrelated, start fresh. In Claude Code, /clear does it, and the docs say it “costs nothing”. Answers often get sharper too, because the AI isn’t wading through old topics.
  2. Save what matters to a file before you leave. A fresh chat remembers nothing, so starting over only works if nothing gets lost. On 25 November I built a small command, /handoff, that has the agent write one short file: the goal, what’s done, the open questions and the next steps. Then I left a chat that was only at 37% of its context, long before any limit, and the new chat picked up from that file instead of the old conversation. Everything I left behind in that chat would have been wasted blocks, like the ones in the chart above.
  3. Send noisy work to a helper. Test runs, big searches and log files fill a chat fast. A subagent, a helper AI with its own space, can do that work and hand back a short summary. It still draws on your usage, but its mess stays out of your main chat. When I attacked my own safety guard, a subagent worked through all 97 attack commands, and my main chat only got the result: 76 of them got through (chapter 3).
  4. Keep the instruction file short. Claude Code reads CLAUDE.md at the start of every session, so every line is paid for every time. Anthropic suggests under 200 lines. On 25 November I followed their advice and cut mine by a third, from 822 words to 547.

The cost docs and best practices cover the rest. Stop the AI early when it heads the wrong way: on a phone that’s the stop button, and in a terminal it’s Esc, with /rewind to jump back. Switch to plan mode with the mode control on a phone, or Shift+Tab in a terminal. And be careful with /compact, because to summarise a long chat the AI has to read all of it first.

My mistake24 Nov 2026

I built a whole website in one chat

I treated one chat as a workspace that never fills up. Every message after the first task paid again for the tasks I had finished, out of the same usage limit all my other work shares. With usage credits off, that limit is where work stops.

The rule nowOne chat per task. My agent now warns me when a session gets long, saves the next steps to a file, and I start fresh.

Check yourself

You’ve spent two hours on your website in one chat. Now you need help with an email. What’s the cheapest move?

Ask the AI to save any website decisions to a file, then start a fresh chat for the email. The email chat won’t carry two hours of website talk.

Why does a short reply cost more at the end of a long chat than at the start of a new one?

Because it gets sent together with everything before it. The reply is small, but the chat underneath it isn’t.

You hand a big search to a subagent. Is it free?

No. It still draws on your usage. What you save is room in your main chat, which gets a short summary instead of the whole search.
