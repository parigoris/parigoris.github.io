Token basics: why long AI chats cost more, and 7 tricks to spend less

24 November 2026

I spent a whole day building this website in one long chat with an AI agent. It worked, but it got expensive. Here's what I learned about tokens, in plain words.

In short

  • What: a beginner’s guide to tokens, the small pieces of text that AI tools count and charge for.
  • Why it matters: every new message makes the AI re-read the whole chat, so long chats about many topics get pricey.
  • Biggest win: one chat per task. Starting fresh is free, and the answers often get better.

What I learned the hard way

I built most of this website in one very long session with Claude Code. We did the design, the colours, the research, a build log and a pile of new ideas, all in the same chat. Everything worked. But by the end, every small question I asked was slow and costly, even a one-line “looks good, thanks”.

The reason turned out to be simple, and once I saw it, I changed how I work.

What is a token?

AI models don’t read words the way we do. They cut text into small chunks called tokens. A token is often a piece of a word, a few letters long. For Claude, Anthropic says a token is roughly 3.5 English characters on earlier models, and newer models cut the same text into a bit more tokens. Other languages and code can split differently.

You pay for tokens (or use up your plan’s limit with them) in two directions: what the AI reads, and what it writes.

Why long chats cost more

Here’s the part that surprised me. The AI has no memory between messages. So each time you send one, the tool sends the whole conversation again: every earlier message, every file it read, every result it got back.

That means:

  • A short question at the end of a long chat still pays for everything before it.
  • A chat that wandered across three unrelated topics re-reads all three on every turn.
  • Tools help a little: recently read text is cached and gets cheaper. But the cache expires after a while, and then the full history is processed again.

So the cost of a message isn’t about how long your message is. It’s about how long the whole chat is.

7 tricks to spend fewer tokens

  1. One chat per task. When you switch to something unrelated, start fresh. In Claude Code, /clear does this, and the docs say it “costs nothing”. The new task stops paying for the old one, and the AI’s answers often get sharper too.

  2. Save what matters in files before you leave. Starting fresh only works if nothing important is lost. Ask the AI to write decisions, research and next steps into a file. The next chat reads that file, not the whole old conversation. I now keep a parked-ideas file and a standards file for exactly this.

  3. Keep your instruction file short. Claude Code reads a file called CLAUDE.md at the start of every session, so every line in it is paid for every time. Anthropic recommends keeping it under 200 lines, because longer files use more space and Claude follows them less reliably. Mine is about 120 lines.

  4. Put the “never ever” rules in a hook, not in text. A written rule is a guideline, and the AI can decide it doesn’t apply. A hook is a small script that runs before every command and simply blocks it. I have one that stops the agent from pushing to my main branch or merging changes. It costs no tokens to remember, and it can’t be argued with.

  5. Send noisy work to a helper. Long test runs, big searches and log files fill up the chat fast. A subagent (a helper AI) can do that work in its own space and hand back a short summary. It still uses tokens, but your main chat stays small.

  6. Be specific, and plan first. “Improve my website” makes the AI look at everything. “Make the footer links bigger on phones” goes straight to the point. For bigger tasks, ask for a plan before any building starts (in Claude Code, Shift+Tab switches to plan mode). Fixing a plan is much cheaper than fixing finished work.

  7. Stop early when it goes the wrong way. Press Esc to stop the AI mid-action. /rewind (or Esc twice) takes you back to an earlier point. And if you’ve corrected it twice and it still isn’t right, start a fresh chat with a better prompt instead of a third correction.

Bonus tip: ask your AI to warn you when a session gets long, then start a fresh one. I added this to my own rules after my long website day, and now my agent tells me when it’s time.

My mistake

I built this whole website in one chat: design, colours, research, ideas, the lot. By the evening, even a quick ‘looks good, thanks’ was slow and expensive, because every message dragged the whole day along with it.

The rule it gave me: one chat per task, and my agent warns me when a session gets long, so I can save the next steps to a file and start fresh.

Be careful with “compact”

Claude Code also has /compact, which shrinks a long chat into a summary. It sounds like a free fix, but to write that summary the AI has to read the whole chat first. On a long session, that’s a big request in itself. Saving the important parts to a file and starting fresh is often the better choice.

Try it yourself

Open Claude Code in any project and type:

/context

You’ll see what’s taking up space right now: your instruction files, tools, and the conversation itself. Then try /usage to see what your session has used so far. Run them again near the end of a long chat, and the difference tells the whole story!

And if you only do one thing, paste this into your instructions file:

When this session gets long or mixes unrelated topics, warn me.
Before I start a new session, save decisions and next steps to a file.
